## 1. 当前基础与开发边界

仓库已有 SKILL.md、AGENTS.md、分游戏知识库和测试报告规范，尚无 Python 包、依赖声明、Runtime 或自动化测试。本机检查到 Python 3.12.8；未检查第三方依赖安装或凭据。README.md 和 docs/ 已有未提交改动，开发应保留。

首版实现 Codex 活动会话 + 常驻 Python stdio MCP + Jev。Codex 提供截图语义、候选与 UI 调度，Jev 选择，Runtime 管理上下文和生命周期。用户本次要求进入开发准备，原设计文档中“本轮只设计”的描述是当时交付边界，不构成对本次工作的额外审批要求。

先建立一个可验证的调用入口，再扩展运行逻辑。暂不增加独立模型宿主、专用视觉服务或游戏专属控制器。现有游戏操作规则继续有效，只有新闭环验收后才替换旧的手写决策与 checkpoint 流程。

## 2. 建议代码布局与职责

采用 src 布局，包名 jev_game_agent；以下为拟新增文件，不表示已经实现：

```text
pyproject.toml
src/jev_game_agent/
  __main__.py             # 固定 stdio 服务启动入口
  config.py               # 设置、路径、预算及启动自检
  contracts.py            # 输入输出模型、枚举与语义校验
  server.py               # 五个 MCP 工具的薄适配层
  runtime.py              # 单运行串行状态机及生命周期
  store.py                # SQLite 事务、幂等、恢复、迁移
  context.py              # 当前局面、历史反馈、预算裁剪
  knowledge.py            # 分游戏检索、依据校验、冲突处理
  decisions/
    base.py               # 可替换决策客户端接口
    typesafe.py           # 官方 SDK、长生命周期连接、错误分类
  exports.py              # checkpoint、缺陷记录与报告导出
tests/
  fixtures/               # 明确标记模拟/重建/真实证据
  test_contracts.py
  test_runtime.py
  test_recovery.py
  test_context.py
  test_decisions.py
```

Runtime 不直接操作浏览器；server 不承载游戏策略；SQLite 是运行事实来源，导出文件只供兼容和阅读。运行数据库放在 run/<run-id>/runtime.sqlite3，遵循现有忽略规则。

依赖暂定为官方 MCP Python SDK、TypeSafe Python SDK、结构化数据校验库和 pytest。实际包名、API、兼容版本与锁定方式在探针开发前阅读官方文档并验证，避免直接根据设计草案写死版本。首次实现后记录依赖版本和运行响应模型。

## 3. 编码前需要具体化的契约

先在 contracts.py 定义模型，再实现流程。以架构中的五个工具和五种返回任务为基础：

- start：url、game_id 或待识别状态、goal、completion_criteria、constraints；生成 run_id，返回观察要求。
- advance：run_id、submission_id、observation、可选 previous_execution；完成验证与判别并返回单个任务。
- resume：返回任务原文、未确认执行及新截图要求；不下发历史操作。
- status：只读状态、待验证动作、问题与耗时摘要；不调用 Jev。
- finish：显式结束原因，区分完成、取消和受阻；不把主动结束一律写成目标成功。

观察必须区分 facts、interpretations、unknowns，包含页面/截图引用、objects、candidates、changes、异常线索。候选绑定本次页面与截图，包含操作参数、语义目标、约束标签、前提及已知效果；不包含推荐排序。

执行回执关联 decision_id，区分工具接受、工具失败、执行未知；视觉结果独立记录成功、失败、未知和证据。工具接受不能代替视觉验证。

EXECUTE 携带来源观察与完整候选；OBSERVE 携带等待上限；ANALYZE 携带有限帮助类别与缺失证据；COMPLETE 携带目标证据；BLOCKED 携带错误类别和恢复条件。

目标证据先由 Codex 根据用户完成条件提供结构化核验，Runtime 检查关联性、当前证据与未验证动作。程序不能仅凭 Jev 选择停止或关键词匹配判定任意自然语言目标完成。

## 4. 首批开发任务和准入条件

### P0：能力探针

交付最小 Python 包、固定启动入口和结构化探针。探针属于部署检查，不增加正式游戏工具数量；可通过 start 的自检路径在实际 MCP 服务中执行验收模式。

1. 验证 stdio 初始化、工具发现、对象输入与结构化返回；stdout 只传协议，诊断写 stderr。
2. 检查服务内部能否读取 TYPESAFE_API_KEY，只输出存在与否，绝不输出值。
3. 核验官方 SDK 实际接口，建立并复用一个客户端。
4. 在同一已注册服务入口连续完成 10 次真实文本 Choice 请求，记录成功数、请求耗时、模型、错误分类及是否逐次审批。使用小型文本场景，不操作游戏。
5. 阅读当前 UI 工具文档，确认页面绑定、截图引用、坐标单位及一次操作参数，形成宿主适配说明。

通过条件：真实 MCP 入口能持续调用，10 次请求无逐次审批且无常规沙箱失败重试；凭据不进入输出；协议无 stdout 污染；UI 执行绑定方式清楚。若宿主策略限制，保留准确失败证据并解决入口问题，不能以终端单次成功替代通过。

本阶段需要实际部署配置和可用 key；本次准备未读取密钥、修改全局配置或发起网络请求。

### P1：最小 Runtime 与账本

交付五个工具、模型校验、SQLite 与一个注入模拟决策客户端的完整闭环，再接入已通过 P0 的真实客户端。

优先实现 start → advance → EXECUTE → 新观察与回执 → 验证 → 下一任务，以及 resume/status/finish。每次 advance 在事务中登记 submission 和输入摘要；相同 ID、相同内容返回保存结果，相同 ID、不同内容拒绝。单运行只允许一个在途判别及一个待执行意图。

需特别覆盖崩溃窗口：

- Jev 返回前中断：保留请求状态，恢复时明确未完成判别。
- Jev 返回后、结果提交前中断：决策可能已收费但未持久化，不承诺外部请求 exactly-once；记录恢复状态，避免误下发动作。
- EXECUTE 已返回但回执未保存：操作是否发生未知，要求新截图核对，不重发旧动作。
- 已存输出的重复 advance：不再次调用 Jev，不产生新的执行意图；宿主同样按 decision_id 防止重复执行返回的任务。

通过条件：幂等、旧观察失效、中断与服务重启恢复均有测试；不会自动重放未知消费/领取/战斗；目标证据不足时不能 COMPLETE。

### P2：上下文与知识

自动维护任务、当前局面、行动反馈、游戏知识。先采用可解释的页面/候选语义检索，不增加向量服务。读取各游戏 maintenance.md 后实现知识写入规则。

保留最近 6 条已验证结果及仍有效阻塞；成功恢复解除对应阻塞；新截图替换当前可见事实。12,000 字符预算保留任务、约束、当前证据、未知项与候选，必要部分超预算返回 ANALYZE。

通过条件：跨游戏知识隔离，公告页面不带整套迷塔攻略；失败摘要不会因窗口裁剪消失；历史信息不会冒充当前可见；知识冲突请求分析而非自动覆盖。

### P3：会话闭环和兼容迁移

在 P0/P1/P2 通过后更新 SKILL.md、AGENTS.md 和 README。将宿主流程改为提供观察 → 调用 advance → 执行返回任务 → 新截图验证；决策、回执与 checkpoint 由 Runtime 保存。

先完成一个小型截图任务，再验证一次按用户定义的迷塔挑战及建筑重新定位。两次已验证无响应时先检查定位与可用控制台；三轮无进展请求分析。等待最长单次 5 秒。

通过条件：宿主不创建中间 JSON 文件，不重选 Jev 动作；分析后恢复 Jev 选择；达到目标即停；异常报告和知识维护符合原规则。

### P4：质量与性能

用同游戏、相近起点与同目标比较纯 Codex 和双模型。记录观察、复杂分析、Jev、工具、编排与总耗时，输入量、完成情况、无效动作和接管次数。每个请求记录候选数、概率、confidence 与结果，供后续校准。

真实数据不足时只报告已测范围，不承诺提速。历史记录缺少截图或候选时标注重建或模拟；第二游戏取得后再验证跨游戏能力。

## 5. 必须覆盖的回归场景

- 正常流程：多个有效候选、页面切换、资源不足、战斗等待、奖励变化、目标停止。
- 证据和约束：未知页面、旧坐标、候选缺失、关键前提未知、非法选项、完成证据不足、知识冲突。
- 可靠性：重复 submission、同 ID 不同输入、并发 advance、迟到响应、操作后中断、服务重启、失效页面绑定。
- 服务错误：认证、格式、网络权限、DNS/TLS/代理、限流、5xx、总体超时；最多一次暂时故障重试且不能重放 UI 操作。

模拟测试验证确定性控制流；真实探针验证网络与部署；截图任务验证视觉闭环。三类结果分别报告。

## 6. 推荐开始顺序

下一次编码先完成 P0 的最小包和探针，同时冻结首版契约。通过真实入口验收后再推进 P1，不一次性铺完所有模块。每阶段提交代码、验证结果和尚未通过的条件；遇到能力限制优先修复入口。

需要在首次实现时决定并记录的细节：实际 SDK/模型版本、宿主支持的 MCP 配置与环境传递、UI 参数绑定、完成核验表达、并发与幂等事务、SDK 重试关闭方式、知识写入与兼容导出格式。架构中的数值暂作为可配置初值，不视作已校准结论。
