# 城镇建筑系统

## 系统名称与用途

城镇建筑产出或加工资源，并通过等级前置关系解锁。已验证范围包括内网开发服资源建筑、地下城、英雄营地相关入口和铁匠铺普通建造；跨建筑和等级的升级通用机制尚未完整验证。升级目标包含完成必要前置后返回升级的路径，依据用户提供规则；净化中枢升级条件另有用户截图支持。

## 入口与识别

主页面是一张可拖动的地图。建筑可能位于视野外，也可能只露出一部分；轻微移动地图可显示建筑名称。按名称确认目标后，点击建筑本体打开专属面板。

## 寻找并打开指定建筑

适用目标：从主页面寻找某座建筑并打开其信息面板。此路径已在内网开发服的净化中枢、木材场、英雄营地、煤炭场、铁匠铺上走通；不预设未来账号的建筑等级、建造状态或固定位置。

1. **观察当前画面。** 若建筑面板或促销遮罩挡住地图，先用当前可见的返回或关闭控件恢复主页面。观察可见建筑及地图边缘，外形只用于初步定位，以名称标签确认目标。
2. **按用途选择拖动尺度。** 按[地图拖动的用途与距离](#地图拖动的用途与距离)区分搜索、调整位置和重显名称。检查起点、终点和整段路径，避开建筑、浅色锁、任务条、GM按钮与导航等交互控件，优先选择空草地。每次只沿一个轴短拖，随后重新截图，核对地图实际移动方向、距离与新出现的建筑。
3. **及时识别名称。** 地图移动后名称显现，应及时观察或截图。标签淡出后，可再次从安全空地轻拖以重新显示；名称的正常淡出不表示建筑消失。时间机制见[建筑名称显示与淡出计时](#建筑名称显示与淡出计时)。
4. **按区域扩大搜索。** 一次拖动未见目标，只能说明当前视野未找到。优先检查当前建筑群及相邻区域，用已识别建筑、道路、河岸和围栏作为参照；首次短拖后确认地形实际移动方向，不凭方向名称猜测。分段搜索，相邻视野保留重叠，在运行记录中简记已检查区域和下一片未检查区域。连续视野只有树林、河道或岩石时，调整方向或返回最近的建筑群，避免沿同一片无建筑地形反复扩展；地形只能用于规划搜索，不能证明其他区域没有目标。只有尽可能检查可到达的建筑区域后仍未找到，才反馈“已检查范围内未找到指定建筑”，同时说明尚未能查看的区域。
5. **确认名称并调整点击位置。** 标签被截断、建筑贴边或与控件重叠时，先调整地图，尽量让目标完整进入画面中部并远离任务条、GM按钮和导航。拖动后重新截图，确认名称和本体，再选择建筑上清晰露出、面积较大的部位点击；铁匠铺曾在重新定位后点击屋顶成功打开，但不能据此假定所有建筑只响应屋顶。每次移动后重新定位，不复用旧坐标。
6. **未打开时先排查定位。** 点击后没有面板时，先确认地图是否仍在移动、建筑是否移位、标签是否淡出，以及点击点是否落在本体或被其他控件覆盖。必要时安全轻拖重显名称、把建筑移到清晰位置，再按操作技能的重试流程选择新的明确点击点。工具确认提交点击不证明命中了建筑；两次未打开也不足以单独认定游戏缺陷。只有排查定位和遮挡后仍有证据支持游戏异常，才按技能的控制台检查与缺陷记录流程处理。
7. **核验面板并停止。** 点击后重新截图，面板标题必须对应指定建筑，例如“木材场 Lv.…”；点击提交成功本身不算完成。若出现其他遮罩，先关闭并重新观察，不能假定建筑已打开。看到对应面板即完成“打开建筑”目标；升级、建造和派遣属于后续独立操作。

### 地图拖动的用途与距离

- 状态：执行规则，经用户要求纳入知识库；以下比例是初始操作尺度，尚未实测校准，不代表游戏固定的拖动响应。
- 尺度基准：以当前截图中可见地图区域沿拖动轴的长度为基准，排除黑边、浏览器外框和固定导航/顶部控件占据的区域。起止点与整段路径必须位于安全可拖区域；若路径不够长，应缩短单次距离并重新观察。
- 搜索建筑：目标尚未出现时，默认沿一个轴拖动约基准长度的三分之一。相邻视野保留可识别参照物和重叠区域；同一段搜索保持相近尺度，只有观察结果支持时才调整。
- 调整位置：目标已出现但贴边或受控件遮挡时，默认拖动约基准长度的十分之一。根据目标与清晰点击区域之间的距离缩短，避免把目标拖出画面。
- 重显名称：仅需恢复淡出的标签时，默认轻拖约基准长度的二十分之一，尽量保持目标可见。若未显示名称，先确认地图是否实际移动，再决定是否调整距离。
- 位移校准：每次拖动后用同一建筑或地形参照物比较前后位置，确认实际移动方向和距离；输入拖动距离不等于实际地图位移。若位移超过预期或目标越过预定位置，下次减小距离；若位移不足，先排查遮挡、起点和地图边界，确认拖动有效后再适当增加距离。接近边界时换方向，不盲目放大距离。
- 执行记录：每次决策说明拖动用途、轴向和选定尺度；运行记录保留实际移动效果及需要延续的尺度调整。截图尺寸或地图布局改变时重新确定基准，不复用旧坐标。
- 核验要求：单次拖动 → 新截图 → 核对位移和目标可见性 → 决定下一步，不能连续提交一串拖动后才观察。
- 适用范围：Fengyu可拖动主城地图；当前已知内网开发服客户端v1.0，构建及特权未知。其他游戏需独立确认。
- 记录日期：2026-10-10。

## 建造或升级指定建筑

1. 找到目标建筑/建造入口，打开标题对应的专属面板；搜索方法见上文。
2. 逐项读取当前建造/升级条件及资源，满足项可显示绿色勾，未满足项可显示红叉。核对资源名称、完整数量、单位（例如“万”）及需求值，并结合勾叉状态判断是否满足；读数不清或数字与勾叉看似矛盾时，重新观察当前面板后再规划前置。只有确认资源不足，才安排补充资源。
3. 条件未满足时，按下面的[完成必要前置后返回升级](#完成必要前置后返回升级)路径先完成依赖。前置属于原建筑目标的必要子任务，完成一个前置不代表建筑升级完成；需要挑战、资源收集或其他建筑升级时，进入对应系统执行。
4. 前置完成后返回原建筑面板，重新核验全部条件、材料和当前等级。若前置自身还有依赖，继续按现场条件处理，直到原建筑升级可执行；遇到无法完成的条件时，保留具体阻塞项。
5. 全部条件满足后使用对应普通建造/升级控件。时间与钻石立即完成是分开显示的；按现场成本选择，不能因已观察到的短计时预设所有建筑都是1秒。目标包含必要前置的常规操作，不自动授权购买、钻石加速或其他受限消费；遵守用户约束和操作技能。
6. 等待完成，再核对建筑成形、完成提示或面板等级变化。以用户指定建筑达到目标等级为结束条件；只说“升级一次”时，记录操作前等级并确认提升一次。资源建筑、净化中枢及地下城普通建造已走通；铁匠铺也通过约1秒普通建造完成。

### 完成必要前置后返回升级

- 状态：用户提供规则；净化中枢的具体条件来自用户提供截图，尚未实测“通关20层后返回升级”的完整流程。
- 结论：用户要求升级某建筑时，可以先完成升级面板列出的必要条件，再返回原建筑升级。执行中保留原目标和目标等级，只推进满足该目标所需的依赖。
- 可复用路径：读取未满足条件 → 按依赖进入对应玩法 → 核验前置完成 → 返回原建筑 → 重新核验条件与成本 → 普通升级 → 确认建筑等级或完成状态。
- 分支处理：其他建筑等级不足时先升级对应建筑；指定挑战未完成时先进入对应挑战；材料不足时通过已知且符合用户约束的获取路径补足。前置有进一步依赖时按同样方式处理，记录依赖关系，避免在建筑与玩法之间无目的往返。不要凭历史知识假定条件已满足。
- 净化中枢示例：用户截图的“需要条件”显示“通关雾隐谜塔20层”为红叉，木材需求200为绿色勾，两个升级按钮呈灰色。此时应先按[雾隐迷塔玩法](tower.md)完成所需通关，核验第20层完成后返回净化中枢；看到挑战条件也满足后，再核对普通升级按钮与材料并执行升级。截图未明确当前建筑等级，不能据此固定某等级永远要求20层。
- 界面判断点：升级面板条件文字及勾/叉、前置玩法的完成结果、返回后的条件状态、升级按钮可用状态、最终建筑等级或完成提示。
- 适用范围：用户确认的建筑升级依赖处理方式；示例为净化中枢升级界面，版本、构建、当前等级和特权未知。条件与成本每次现场核验。
- 记录日期：2026-10-10。
